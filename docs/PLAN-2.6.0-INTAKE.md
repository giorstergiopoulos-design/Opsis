# PLAN 2.6.0 — απογραφή και πρόταση σειράς (intake)

Ημερομηνία: 2026-11-10 · Συντάκτης: session Opsis (Sonnet) · Πηγή εντολής: `OPSIS_UNIFIED_MASTER_PLAN.md` (Απόφαση Στρατηγικής, 0Β, 0Γ, 0Δ, 0) και `TASKS-MASTER.md` §26.
**Δεν ξεκίνησε υλοποίηση. Δεν διαγράφηκε κανένα αρχείο.** Αυτό το έγγραφο είναι μόνο (α) απογραφή, (β) πρόταση σειράς και σχέδιο Φάσης 0Α, για έγκριση και προτεραιότητες από τον χρήστη.
Κατάσταση βάσης: Opsis **2.4.6** (τοπικά commits· assets στο `release/2.4.6-assets`), 164 tests. Οι ετικέτες στήλης «Τώρα»: **ΕΤΟΙΜΟ** (υλοποιημένο στο 2.2–2.4.6), **ΜΕΡΙΚΟ**, **ΑΝΟΙΧΤΟ**, **ΘΑ ΑΝΤΙΚΑΤΑΣΤΑΘΕΙ** (λύνεται από τον νέο πυρήνα), **ΔΙΑΓΡΑΦΗ-ΖΗΤΕΙΤΑΙ** (το σχέδιο ζητά κατάργηση).

## 1. Κανόνες που ισχύουν (σύνοψη για τον έλεγχο)
- Μόνο **Opsis 2.6.0 beta** (κλάδος `2.6.0-beta`, ποτέ στο `main`). Παλιός κώδικας: μόνο μικροέκδοση **2.4.6.1** (σταθερότητα/plugins, συγκρούσεις συντομεύσεων Windows, φθηνά CPU/RAM fixes). Κανένα νέο feature ή «κύμα υγιεινής» στο 2.4.x.
- §0Β.0: καμία συνεχής επαναλαμβανόμενη διόρθωση/έλεγχος· διορθώνω μόνο δικά μου λάθη κατά τη συγγραφή ή σοβαρά ευρήματα (απώλεια δεδομένων, crash, ασφάλεια, κρυμμένα εικονίδια χωρίς επαναφορά)· τα υπόλοιπα → λίστα R για το pre-release.
- Δεν γράφεται κώδικας πριν δώσει ο χρήστης προτεραιότητες. Φάση 0Α (reuse audit) πριν το χτίσιμο του νέου πυρήνα DeskContainers.
- UI: WinForms για όλο το Opsis· **DeskContainers WPF** ως top-level παράθυρα του ίδιου process· glass `Opsis.Glass` (Direct2D)· κοινός κώδικας χωρίς εξάρτηση από UI toolkit. Μόνο Windows 11 στην 2.6.0.

### 2.5 Πόροι (§0.4δ, §9) και λίστα R
- Baseline μέτρησης **στην 2.4.6.1** (όχι 2.4.6): idle/σε χρήση, CPU, Working Set/Private Bytes, GDI/USER objects, handles, GC. Η μέτρηση που έκανα (2.4.0) ήταν idle χωρίς ενεργά τμήματα (Low 0,72 % / High 0,53 %, ~100 MB) — **δεν επαρκεί** ως baseline.
- Soak test: **αυτόνομο εργαλείο καταγραφής** που ξεκινά ο χρήστης (όχι μέσα από συνεδρία Claude)· ή επιταχυνόμενοι κύκλοι ζωής σε λεπτά.
- Λίστα R (§R.1–R.4): τηρείται ως έχει στο plan· τα δικά μου αντίστοιχα ανοιχτά (CHANGELOG 2.4.x «Υπόλοιπο») ενσωματώνονται εκεί, όχι νέα αιτήματα.

## 4. Υποψήφια για **2.4.6.1** (φθηνά, μόνο σταθερότητα/πόροι/συντομεύσεις) — προς έγκριση
Κριτήριο §0Β.1: «χρειάζεται για να δουλεύουν σωστά τα plugins/η σταθερότητα τώρα;». Όλα μικροαλλαγές:
1. **Audit συντομεύσεων Opsis** (global hotkeys: HotkeyManager, Spot Search Ctrl+`, DeskFlip, Ctrl+K, Ctrl+Alt+Arrow, Ctrl+Shift+Arrow κ.λπ.) έναντι της λίστας Windows· διόρθωση μόνο όσων συγκρούονται.
2. **CPU:** `PerformanceProfile.FeatureOverride` διαβάζει το `AppSettings` από τον δίσκο σε κάθε κλήση (δημιουργία timer widget, ανά αλλαγή governor) — cache με invalidation (δικό μου λάθος, 2.4.0).
3. **RAM/GDI leak (Opsis.UI):** το `FlatToggle.BadgeWidth` δημιουργεί `Font` ανά κλήση χωρίς Dispose (`DescriptionFont`)· διορθώνεται με `using`/cache.
4. **Plugins:** τίποτα επιπλέον — η σταθερότητα (snapshots, εκκρεμείς εγκρίσεις, transient errors) έχει ήδη γίνει (2.4.4).
5. Οι δύο διορθώσεις ασφαλείας του fork (νεκρές εντολές tray, `Environment.Exit` που παρακάμπτει την επαναφορά εικονιδίων) — **μόνο αν** επιβεβαιωθεί ότι επηρεάζουν σταθερότητα· διαφορετικά → R.2.
Όλα τα υπόλοιπα (κάρτες UI, rubber-band, glass κ.λπ.) **δεν** μπαίνουν στη 2.4.6.1.

## 6. Φάση 0Α (reuse audit) — σχέδιο, χωρίς κώδικα
**Παραδοτέα (όπως ορίζει το plan §2.4.C):** `docs/REUSE_AUDIT.md`, ενημερωμένος πίνακας κόστους/κινδύνων, λίστα αδειών + `THIRD_PARTY_NOTICES.md`, αίτημα προς τον χρήστη για ό,τι δεν είναι προσβάσιμο.
**Μέθοδος (μόνο ανάγνωση και ταξινόμηση, ταχύτητα προτεραιότητα):**
1. **Παλιός πυρήνας `containers/`:** για κάθε αρχείο/κλάση του πίνακα Α του plan (δεδομένα/sanitize, `ContainersMigration`, `WshShim`, rules/automation, `ProfileManager`, `DesktopIconVisibilityEngine`, hooks, icon extraction, `DCM.*` μεταφράσεις, self-tests, snap/roll-up/tabs/portals/notes) → ταξινόμηση **Α** (ως έχει) / **Β** (προσαρμογή) / **Γ** (ξανάγραμμα) / **Δ** (νεκρό), με μέτρηση γραμμών και εξαρτήσεων WPF. Ήδη γνωστό: ~36k γραμμές fork· δικά μας προσθήκες (`OpsisBridge`, `SettingsMenu`, `DesktopOriginals`, `OpsisPerf`).
2. **Κώδικας του Opsis:** `AtomicFile`, `GlassBlur`, `AutomationService`, `WorkspaceProfileService`, `PerformanceProfile`/`PerformanceGovernor`, `ProcessFreezer`, `ZoneSnapEngine`, `PluginHost`, `ZoneOverlayWindow` (layered), widgets/DeskStrip rendering → σχεδόν όλα **Α**.
3. **Άλλα repos (ανάγνωση + άδεια):** PecoFence (Apache-2.0 κατά τις πηγές· `liquid_glass.rs`, `gpu_glass.rs`, rules engine, plan-restore), LockscreenGif, Rainbow-Music-Visualizer-Wallpaper (+ γραμματοσειρές), FluentFlyout, repo macOS wallpaper (**σύνδεσμος ζητείται από τον χρήστη**), Crawler/Appearance/Media Suite/GearWin/Κόμβος για διπλότυπο κοινό κώδικα προς `opsisui`.
4. **Άδειες πρώτα:** πραγματικό αρχείο LICENSE κάθε repo (όχι υπόθεση)· MIT/Apache/BSD → αντιγραφή με attribution (LICENSE + NOTICE + σημείωση αλλαγών)· GPL/χωρίς άδεια → μόνο μελέτη λειτουργίας και ανεξάρτητη υλοποίηση, όχι αντιγραφή.
5. **Spike πριν την κλειδωμένη απόφαση:** μικρό WPF top-level παράθυρο container με Direct2D glass bitmap πάνω σε ζωντανό wallpaper, DPI 100–200 %, πολλαπλές οθόνες, διαφάνεια — αν αποτύχει, fallback WinForms layered.
